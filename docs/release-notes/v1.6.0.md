## New

**A workspace opens several tabs.** In the workspaces file, a `tab` line starts a tab, and the `main`, `right`, `bottom` and `focus` lines under it belong to that tab. `tab = name` pins the tab's title; a bare `tab` shows the live title. Opening the workspace, or a worktree of it, starts every tab in order and puts the cursor where `focus` says. A file written before tabs existed reads as one tab, as it always did. [`docs/config/workspaces`](https://github.com/praxis-labs-io/zen-term/blob/main/docs/config/workspaces) has the format.

**One form for adding and editing a workspace.** Add Workspace… in ⌘P and Settings → Workspaces open the same form. Its tabs sit in a strip: add one, double-click to rename it, drag to reorder, and remove it with Undo on hand. Each tab is drawn as its main pane and two drawers, and you type the command for each one where it sits. ⌘L sets where the cursor lands when the workspace opens. The tab shortcuts work inside the form too: ⌘T adds a tab and ⌘⌥W removes one.

## Changed

**The Editor + AI + Shell preset is gone.** The form above replaces the three layout choices. Workspaces you already saved keep their commands and open as before. The `editor` config key only fed that preset, so it is gone as well, and ZenTerm ignores it if it is still in your config. The `ai` key stays, and does one thing now: it names one more program that counts as an agent. Neither one is in Settings any more.

## Fixed

**The sidebar missed a branch switch.** Switching branches in a pane left the sidebar showing the old one until you left the window and came back. It now catches up within a couple of seconds.

**A notice could outlive coming back to the window.** Returning to ZenTerm cleared the card for an agent that had finished in a pane you could see, but left others up: a notice from a drawer, or from a program that is not an agent. Every card for a pane or drawer in view now clears when the window comes back.

**ssh to a host without ZenTerm's terminfo.** ZenTerm sets `TERM=xterm-ghostty`, and a remote host without that entry could not draw its line editor and echoed stray characters. ssh from a ZenTerm shell now gives the remote session `TERM=xterm-256color`, and `COLORTERM` comes across with it.

## Install

ZenTerm updates itself. On v0.2.0 or later, the update card appears in the app. For a first install, open the DMG and drag ZenTerm to Applications. macOS 14 or later, Apple Silicon.

## Reporting a bug

From inside the app: Help → Report an Issue prefills the version and your environment. You can still open an [issue](https://github.com/praxis-labs-io/zen-term/issues) directly.
