## New

**Report an Issue.** A composer built into the app. Give it a title and what happened, see the environment it will attach, and it opens a prefilled issue on the public tracker. Reach it from Help → Report an Issue, from the bottom of Settings, or the command palette (⌘P). It ships without a chord, so bind `report_issue` if you want it on the keyboard.

**Export Diagnostics.** Help → Export Diagnostics saves a zip of your logs and system info (app and macOS version, architecture) to attach to a bug report. It carries only that: your shell environment and your config file stay out of it.

## Changed

**Config mistakes surface now.** An invalid value, an out-of-range number, a dropped float line: each used to fall back to the default with nothing said. Now the problem shows on the Settings row that owns it, and a reload toast carries an Open Settings button that lands on the first one.

**`toggle_repo_picker` is now `toggle_workspace_picker`.** The shortcut action takes the app's word, workspace. The old name still works if it's in your config, and saving from Settings rewrites it to the new one.

**Dock tooltips show the shortcut.** A tool float's dock button names its toggle shortcut in the tooltip and follows a rebind, matching the fixed dock buttons and the command palette.

## Fixed

**Updates get noticed after a launch.** ZenTerm checked for a new version at most once a day, so a terminal opened and closed through the day could sit on an old build without the update card ever appearing. It checks hourly now, so a normal launch finds the update.

## Install

ZenTerm updates itself. On v0.2.0 or later, the update card appears in the app. For a first install, open the DMG and drag ZenTerm to Applications. macOS 14 or later, Apple Silicon.

## Reporting a bug

Now from inside the app: Help → Report an Issue prefills the version and your environment. You can still open an [issue](https://github.com/zen-term/zen-term-releases/issues) directly.
