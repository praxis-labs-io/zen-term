## New

**A window holds several workspaces.** A workspace used to be a tab you opened from ⌘P. It is now a layer above tabs: each one holds its own tabs, its own layout and its own title, and the window takes the name of the one you are in. Switch with ⌘⌃1 through ⌘⌃9, step with ⌘⌃[ and ⌘⌃], and open one with no config entry on ⌘⌃T, which starts in your home folder. The [Workspaces guide](https://zenterm.io/docs/workspaces) walks through it.

**The workspace sidebar.** ⌘⌃S docks it down the left of the window, and ⌘⌃S again collapses it. It lists the window's workspaces with their branch, and nests each workspace's worktrees under it. The footer carries the command palette and Settings. A new window opens the way you last left it.

**The sidebar reveals itself while collapsed.** Point at the window's left edge and the sidebar floats in as a card over the panes, close enough to click a row without docking anything. Move away and it leaves. On a window too narrow to dock into, it floats rather than taking the space.

**Agents are listed in the sidebar.** An Agents section under the workspaces lists what is running in the window, sorted waiting, working, done, then idle. A row says which workspace its agent is in, and clicking it or pressing Return switches workspace, selects the tab and focuses the pane, opening a closed drawer to get there. A workspace row carries a dot while an agent inside it is waiting on you, so a collapsed sidebar still has something to say.

**The sidebar takes the keyboard.** Arrows move focus between rows, Return activates one, and Esc hands focus back to the pane. ⌘⌥← past the leftmost pane lands in the sidebar and ⌘⌥→ comes back out. Right-click a row for its menu, with New Worktree and Close Workspace, and hover a configured workspace to cut a worktree from its row.

**New Worktree from a sidebar row.** ⌥⏎ on a focused row opens the same card the picker does, and the worktree opens nested under the workspace it came from.

## Changed

**Two default shortcuts moved.** ⌘⌃[ and ⌘⌃] moved the active tab along the bar through v1.4.0. They switch workspaces now, and moving a tab is ⌘⌥[ and ⌘⌥]. If you bound `move_tab_left` or `move_tab_right` yourself, your chord is untouched. The [Shortcuts guide](https://zenterm.io/docs/shortcuts) and [`docs/config/config`](https://github.com/praxis-labs-io/zen-term/blob/main/docs/config/config) list every default.

**Each close shortcut means one thing.** ⌘W closes the focused pane or drawer, takes the tab with the last pane, and takes the window with the last tab. ⌘⌥W closes the tab whatever it holds, ⌘⇧W closes the window, and ⌘⌃W closes the workspace. Anything that would end something still running asks first and names it, including a middle-clicked tab and the window's own close button, which both went straight through before.

**⌘P groups what it lists.** The picker was a flat list that could not say which workspaces were running. It has three sections now: Open in this window, Open Elsewhere in another, and Configured for the rest, with fuzzy matching ranking each one. New Workspace leads it and Add Workspace sits at the foot. A workspace's unopened worktrees stay reachable while the workspace itself is open.

**Opening a workspace that is already running brings its window forward.** Choosing one open in another window used to start a second copy of it, which ran the layout again and could put a second dev server on the same port. It now raises the window that has it.

**⇧⏎ in the picker no longer replaces the current tab.** Enter opens the workspace, or switches to it when it is already open.

## Fixed

**A pane kept reporting the mouse from under a cover.** A pane under a tool float, Scratch, the command palette, Settings or a confirm card went on telling its program where the cursor was, so a full-screen program underneath reacted to a pointer that was over something else. Clicks never leaked this way and still do not. Dragging a selection inside a float no longer reaches the pane below it either.

## Install

ZenTerm updates itself. On v0.2.0 or later, the update card appears in the app. For a first install, open the DMG and drag ZenTerm to Applications. macOS 14 or later, Apple Silicon.

## Reporting a bug

From inside the app: Help → Report an Issue prefills the version and your environment. You can still open an [issue](https://github.com/praxis-labs-io/zen-term/issues) directly.
